AI Blocks let you add LLM-powered steps directly to a Mage Pro pipeline. Use them
when the pipeline itself needs to call an AI model during execution, return a
validated response, generate code, or decide whether another pipeline should run.

Use **AI Sidekick** when you want an interactive assistant in the Mage UI. Use an
AI Block when you want AI behavior to become part of a repeatable pipeline.

## When To Use AI Blocks

Use AI Blocks to:

- summarize, classify, transform, or enrich text during a pipeline run
- return structured data that downstream blocks can consume
- generate code or SQL and optionally validate it before saving
- route work to another pipeline by exposing that pipeline as a tool
- add LLM-based checks to a broader automation or RAG workflow

## How AI Blocks Work

An AI Block is configured with YAML. At minimum, the block needs a `prompt`.
Optional sections control the expected output and any tools the model can use.

```yaml
prompt: Summarize the input text in two sentences.
```

For production workflows, define the output shape or validation rules so
downstream blocks receive predictable results.

## Configuration Reference

### prompt

The instruction sent to the model.

Use a multi-line prompt when the task has multiple requirements:

```yaml
prompt: |
  Review the customer feedback.
  Return the main sentiment, the product area mentioned, and one suggested action.
```

### output.code

Use `output.code` when the block should produce executable code or SQL.

```yaml
prompt: |
  Write a SQL query that counts daily active users by signup cohort.
output:
  code:
    save: true
    validation: Ensure the SQL is valid and only references known tables.
    language: sql
    profile: default
    client: postgres
```

Common fields:

| Field | Description |
|---|---|
| `save` | Saves generated code for reuse when enabled. |
| `validation` | Adds instructions for validating generated code. |
| `language` | Sets the expected language, such as `python` or `sql`. |
| `profile` | Selects a SQL connection profile from `io_config.yaml`. |
| `client` | Sets the SQL client type. |

### output.format

Use `output.format` when downstream blocks need structured values.

```yaml
prompt: Extract customer details from the text.
output:
  format:
    name:
      type: string
      description: Customer's full name
    email:
      type: string
      format: email
    priority:
      type: string
      enum:
        - low
        - medium
        - high
  validation: Ensure all required fields are present.
```

### validation

Use `validation` to describe how Mage should check the model response before the
pipeline continues.

```yaml
prompt: Classify the support ticket.
output:
  format:
    category:
      type: string
    reason:
      type: string
validation: Return only categories used by the support team.
```

### tools

Use `tools` when the AI Block should choose from approved Mage pipelines and pass
variables into the selected pipeline.

```yaml
prompt: Analyze the customer request and decide whether follow-up processing is needed.
tools:
  prompt: Choose the best pipeline for the request.
  required: true
  pipelines:
    - uuid: customer_followup
      description: Creates follow-up tasks for high-priority customer requests.
      blocks:
        - uuid: create_tasks
      variables:
        customer_id:
          type: string
        priority:
          type: string
          enum:
            - medium
            - high
```

## JSON Schema Support

The `output.format` and `tools.pipelines.variables` fields use a JSON Schema
draft-07 subset to describe structured values.

Supported schema options include:

- `type`
- `description`
- `enum`
- `items`
- `minItems` and `maxItems`
- `pattern`
- `required`
- `oneOf`, `anyOf`, and `allOf`
- `$ref` and `$defs`

Example:

```yaml
output:
  format:
    email:
      type: string
      format: email
    signup_date:
      type: string
      format: date-time
```

## Examples

### Summarize Text

```yaml
prompt: |
  Summarize this document in five bullet points.
  Call out any risks or missing information.
```

### Return Structured Data

```yaml
prompt: Extract the customer, product, and requested action from the message.
output:
  format:
    customer:
      type: string
    product:
      type: string
    requested_action:
      type: string
  validation: Ensure the output can be parsed by downstream blocks.
```

### Generate SQL

```yaml
prompt: |
  Create a SQL query that returns weekly revenue by plan.
  Exclude test accounts.
output:
  code:
    save: true
    language: sql
    profile: default
    client: postgres
    validation: Ensure the query is valid SQL and includes a week column.
```

### Trigger Another Pipeline

```yaml
prompt: Decide whether the request needs enrichment before export.
tools:
  prompt: Trigger the enrichment pipeline only when customer metadata is missing.
  required: false
  pipelines:
    - uuid: enrich_customer_records
      description: Adds missing customer metadata before export.
      variables:
        customer_id:
          type: string
```

## Best Practices

- Keep prompts specific and focused on one job.
- Use `output.format` when another block depends on the response.
- Use `output.code` only when the expected output is executable code or SQL.
- Do not define `output.code` and `output.format` for the same block.
- Add `validation` for outputs that affect production data or downstream control
  flow.
- Expose only the pipelines and variables the AI Block needs when configuring
  tools.
- Use AI Sidekick to prototype prompts, then move stable behavior into an AI
  Block when it needs to run repeatedly.
