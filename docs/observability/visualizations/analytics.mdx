Analytics turns the data already flowing through Mage into interactive dashboards for business
reporting, operational insight, and team decision-making. Use it to explain revenue trends,
customer growth, product adoption, campaign performance, data quality, model behavior, warehouse
costs, and any other metric your pipelines produce.

Instead of exporting data to another tool before anyone can understand it, teams can create and
refresh dashboards directly where the data is prepared. Analysts, data engineers, operators, and
business stakeholders can all work from the same trusted source.

Analytics is different from monitoring. Monitoring tells you whether your pipelines, schedules,
logs, alerts, and infrastructure are healthy. Analytics tells you what the data means and what your
team should do next.

## Access Analytics

Select **Analytics** in the left navigation, or go directly to:

```text
/apps/analytics/dashboards
```

This is the Analytics workspace. From there, you can create dashboards, open existing dashboards,
add charts, edit charts with AI, refresh data, and arrange the dashboard layout.

## What Analytics helps you do

Analytics is built for fast, practical answers:

| Goal | Example |
| --- | --- |
| Track business performance | Revenue, churn, expansion, renewals, account health, conversion, and retention. |
| Understand product usage | Weekly active users, feature adoption, activation, engagement, and funnel drop-off. |
| Operate data workflows | Failed records, validation errors, source freshness, SLA checks, and quality trends. |
| Review customer operations | Support volume, ticket aging, onboarding progress, and customer success risk. |
| Monitor models and experiments | Accuracy, drift, feature importance, confusion matrices, and experiment results. |
| Analyze warehouse or infrastructure spend | Cost by source, team, warehouse, workflow, or time period. |

Dashboards can include time series, comparisons, distributions, rankings, tables, heatmaps, funnels,
scorecards, and other visual summaries. Start with the business question you want answered, and
Mage helps turn the available data into a useful view.

## Create a dashboard

1. Open `/apps/analytics/dashboards`.
1. Click **New dashboard**.
1. Name the dashboard for the audience or decision it supports, such as `Executive revenue`,
   `Customer health`, `Product adoption`, or `Data quality`.
1. Open the dashboard.
1. Click **Add chart** to create the first visualization.

Keep dashboards focused. A good dashboard usually answers one type of question for one audience:
executive reporting, growth analysis, customer operations, data quality, model review, or cost
tracking.

## Add charts with AI

Click **Add chart**, then describe the outcome you want. AI Sidekick uses the dashboard and the
data you are working with to create the chart and save it to the dashboard.

Useful prompts describe the metric, segment, time range, and decision:

```text
Show monthly recurring revenue by plan type and highlight net revenue retention.
```

```text
Compare weekly active users by customer tier for the last 12 weeks.
```

```text
Show failed records by data source and list the most common validation errors.
```

```text
Create a model quality dashboard with accuracy, recall, precision, and drift by week.
```

You can also create a chart while reviewing pipeline results. Click the chart action from a
supported result or preview, describe what you want to see, and Sidekick keeps the chart connected
to the right data.

For an existing chart, use **Edit with AI** to ask for changes:

1. Change the metric, grouping, or time period.
1. Add a comparison line or segment split.
1. Rename the chart or clarify labels.
1. Turn a trend into a ranking, scorecard, table, or heatmap.
1. Simplify a noisy chart for an executive audience.

## Choose the right data

Analytics can visualize the data your Mage project already works with:

| Data source | Customer outcome |
| --- | --- |
| IO data sources | Build dashboards from connected databases, warehouses, object storage, APIs, and other sources your project can already read from. |
| Pipeline block outputs | Turn the results produced by loaders, transformers, exporters, and custom blocks into dashboards without moving data into another BI tool first. |
| Pipeline runs | Chart run volume, success rate, duration, freshness, or business metrics captured each time a pipeline runs. |
| Block runs | Compare block-level outcomes, failures, processing time, row counts, validation results, or model metrics across runs. |
| Data previews | Explore a dataset, choose the columns and shape that answer the question, then save a chart from the preview lineage instead of only the visible row window. |
| Warehouse-backed data | Summarize large tables into focused metrics before they appear on the dashboard. |
| Transformed datasets | Apply business logic, cleanup, or grouping before the chart is shown. |
| Structured workflow outputs | Visualize tables, records, metrics, matrices, rankings, and other useful shapes produced by your workflows. |

That means Analytics can cover both business data and workflow activity. For example, one
dashboard can show revenue by customer segment, failed records by source, pipeline run duration,
block run failures, and model quality by training run.

When you build charts from pipeline or block outputs across multiple runs, Sidekick checks the
output grain before choosing the chart. Run-summary outputs are useful for operational trends such
as run volume, checked time, row counts, failures, and block duration. Business-date charts, such as
deals by close date or invoices by paid date, need rows that represent the business records and a
matching business date field. If the available output only contains run summaries or nested saved
state, Sidekick should state that coverage before saving the chart.

For pipeline and block output datasets, Analytics chart creation uses the real saved output data
for the selected run or partitions. JSON-backed outputs use readable `data.json` backing data. Chart-backed
datasets do not use `sample_data`, `sample=True` output reads, or `sample_data.json` preview
artifacts to create or refresh charts.

For large datasets, ask for the summary you need rather than every raw row. For example, ask for
"weekly active users by plan for the last 12 weeks" or "top 20 accounts by expansion revenue" so
the dashboard stays fast and readable. When a chart starts from a data preview, Analytics uses the
preview source and query plan to build a chart-owned dataset snapshot; it does not use only the
rows currently visible in the preview table.

Analytics stores a bounded chart-ready snapshot for each saved chart. If Sidekick warns that a
time-series or ordered chart may have reached its dataset preview limit, narrow the request, group
the data into coarser buckets, or ask Sidekick to state the covered date or category range before
using the chart for decisions.

## Organize dashboards for the team

Each chart appears as a card on the dashboard. You can:

1. Rename charts so viewers immediately understand the metric.
1. Edit charts with AI as the question changes.
1. Duplicate a chart to test another view without losing the original.
1. Drag charts into a new order to create a clear story from top to bottom.
1. Resize charts so the most important metrics get more space.
1. Group related charts together so trends, drivers, and details are easy to scan.
1. Remove charts that are no longer useful.
1. Refresh charts when the underlying data has changed.

Use the top of the dashboard for the metrics that matter most. Put detailed breakdowns, tables,
and diagnostics after the summary so viewers can move from signal to detail.

Dashboard layouts are flexible. Drag a chart to rearrange the page, make headline metrics larger,
give detailed tables more room, or place related charts side by side. This makes it easy to turn a
collection of charts into a polished dashboard for a meeting, executive review, customer health
check, or recurring operational workflow.

## Inspect a chart's source and saved query

Open the chart's action menu and select **Chart details** to inspect its saved source details.
Supported saved queries appear in their native format: SQL, MongoDB JSON, or search text. Click
**Copy** to copy the displayed query. Charts without a retained query show their available source
details and **No saved query is available for this chart.** Redacted queries remain hidden.

Saved chart operations or transformations may further shape the results; this view does not
reconstruct the final executed statement. Opening details or copying a query does not run it,
refresh the chart, or change its source.

## Email dashboard snapshots

Send dashboard snapshots for recurring reviews or to people outside Mage Pro. Users with permission
to manage a dashboard can configure its email schedule, send tests, and retry eligible deliveries.
Mage checks the delivery user’s access to the dashboard and its chart sources.

To schedule an email:

1. Open an Analytics dashboard and select **Schedule email delivery** from its actions menu.
1. On the **Schedule** tab, turn on **Schedule enabled** and choose **Once**, **Daily**, **Weekly**, or **Monthly**.
1. Set the delivery time, search for and select a timezone, then enter a subject and message.
1. Under **Send this dashboard to**, enter each recipient's email address and select **Add**.
1. Select **Save**.

There is no weekday or date selector. If today's delivery time has passed, **Once** and **Daily**
start tomorrow, **Weekly** starts in seven days, and **Monthly** starts next month. Weekly schedules
repeat on that weekday; monthly schedules use the day of the month when set, or the last day of shorter months.
A **Once** schedule is disabled after its delivery is queued. Check **Next delivery** or **Next delivery after save** in the selected
timezone before saving.

Deleting a dashboard retires its email schedule. If you recreate the dashboard, configure and save
a new schedule.

An active schedule or test requires at least one recipient. You can save an inactive draft without
recipients. Only the addresses you explicitly add receive the email; you are responsible for
checking that each recipient should receive the dashboard data. Adding an email recipient does not
grant access to the live dashboard or change its sharing policy.

Select **Send test** to queue a snapshot using the current form values. Sending a test does not save
or activate the schedule; select **Save** separately. Scheduled emails, tests, and retries need the
scheduler service to run.

Successful emails include a PDF attachment. Emails can also include embedded dashboard, chart, or
page images when supported and within delivery limits.
Each chart's **Data from** label matches its saved dashboard freshness information. The date may
reflect when the chart was saved, rather than when the underlying source data was updated.

Use the **History** tab to check delivery dates, statuses, recipients, attempts, and errors.
Viewers can open it from the dashboard actions menu using **View email delivery history**;
recipient addresses and errors are hidden from users without editor access to the relevant project or pipeline.
**Queued** means delivery is still being processed or awaiting a provider update. **Sent** means the
email provider or server accepted or reported the message as sent; it does not guarantee inbox
receipt. Some failed scheduled deliveries retry automatically, and **Retry** is available for
eligible failures. For unknown or partial outcomes, retry may be unavailable. Verify who received
the email before creating a new delivery to avoid duplicates.

Email delivery requires configured Mage managed email or SMTP. Contact your
administrator if delivery is unavailable.

## Refresh data

Analytics dashboards are meant to stay useful after the first version. When the source data
changes, refresh the chart or dashboard so viewers see the latest available results.

Charts with loaded data stay visible and dim while refreshing, so you can view the previous
results until the new data is ready. A moving indicator marks the refresh; with reduced motion
enabled, charts dim without animation.

Refresh is useful for recurring reporting:

1. Daily revenue and usage snapshots.
1. Weekly customer health reviews.
1. Data quality checks after each pipeline run.
1. Model evaluation after new training or scoring jobs.
1. Warehouse cost reviews at the end of a billing period.

If a refresh cannot complete, Mage keeps the previous dashboard view available so your team does
not lose the last known good result.

### Choose pipeline output partitions

For a chart backed by pipeline block outputs, open the chart's **Data source** action to choose
which partitions it reads when you refresh:

| Selection | Refresh behavior |
| --- | --- |
| Fixed partition | Re-read the saved run or execution partition. New pipeline runs do not change the selected source. |
| Latest partitions | Re-select the newest N distinct completed execution partitions. Set Partition count to `1` to follow the latest completed partition. |
| All partitions | Re-select all completed execution partitions within the safety limits below. |

Latest partitions and All partitions select partitions again on each explicit chart or dashboard
**Refresh**, while keeping the chart's saved query and transformations. Reloading the page alone
keeps the saved chart snapshot. Partitions are ordered by run completion time, newest first.
Retries for the same execution partition
count as one partition. These settings apply only to charts backed by pipeline block outputs;
other data sources keep their existing refresh behavior. Existing charts also keep their saved
source behavior until you change this setting.

Choose Latest partitions when each partition contains a new batch of records. If each run produces
a full snapshot, combining partitions can repeat records; use a count of `1` to chart the latest
snapshot.

Selection is limited to 1,000 partitions and 10,000 scanned runs. If selection exceeds a safety
limit, or a selected output is missing or unreadable, refresh fails explicitly instead of silently
showing an incomplete selection. Narrow the partition selection or restore the missing output,
then refresh again. All partitions does not remove the chart dataset's separate row limits.

You can also ask Sidekick to change a chart's partition selection:

```text
Make this chart use the latest completed partition whenever I refresh it.
```

```text
Use the last 7 completed partitions from this block for this chart.
```

The saved source field is `source_ref.partition_selection`. Its `mode` is `fixed`, `last_n`, or
`all`; `last_n` also requires a positive integer `count`, for example:

```json
{
  "partition_selection": {
    "mode": "last_n",
    "count": 1
  }
}
```

## Share a dashboard or chart externally

External sharing creates a read-only link that recipients can open without a Mage account.
Workspace Editors, Admins, and Owners can create links directly from Analytics. Editors can
manage their own links; Admins and Owners can also manage other users' links. Viewers do not
see the sharing controls and cannot create or manage links.

The creator must also have access to the dashboard or chart and each included data source.

<Warning>
Recipients can access the chart data included in the shared view, including data available
through hover details, legend toggles, and other interactions. Hiding a series or zooming into
part of a chart does not remove its data from the shared view. Public links do not verify recipient
identity or apply different row or customer permissions for each recipient. Do not share data
that requires those restrictions; prepare a separate output suitable for the intended audience.
</Warning>

### Create a link

1. Open a dashboard and click **Share**, or open a chart's menu and select **Share chart**.
1. On **Create link**, confirm **Scope** shows the intended chart or full dashboard and chart
   count, then choose **Snapshot** or **Live**.
1. Choose an expiration from 1 to 30 days and optionally enter an access code of at least
   8 characters. The default expiration is seven days.
1. Check **I understand recipients can view all data shown in this shared view.**
1. Click **Create link** and wait for preparation. Once ready, choose **Copy link**.

Changing the mode, expiration, or access code starts a new link configuration and keeps your
acknowledgment checked. It does not change or revoke a link you already created; use
**Manage links** to revoke an existing link.

Links and access codes can be forwarded. For a protected link, recipients enter the code
provided by the sender and choose **View Analytics**.

| Mode | What recipients see |
| --- | --- |
| Snapshot | An interactive chart captured during link preparation. Its data and presentation stay frozen for that link. |
| Live | Interactive charts refreshed in the background every 15 minutes, within the saved source and query scope. Opening the public page does not run a query. |

The timestamp at the top shows when Mage captured or last refreshed the shared view.
Each pipeline chart shows when its most recently written selected output was saved. SQL charts
show when Mage fetched the query result. A snapshot captured today can therefore contain a
pipeline chart from yesterday alongside a SQL chart fetched today.
When Mage reuses a saved SQL result, the chart shows that result’s original capture time.
If the data time is unknown, the chart indicates that it is unavailable.

Saved filters, run/partition selection, zoom, and legend state are preserved where supported.
Recipients can use supported zoom and pan controls. **Reset view** restores the chart's captured
starting view, including saved zoom and legend selections. Image exports, cloud actions, and
private editing tools are unavailable.

### Currently supported charts

Sharing uses the chart's rendered Plotly output, preserving its chart type, multiple series,
and supported interactions. This includes bar, line, scatter, pie, donut, histogram, box,
violin, heatmap, funnel, treemap, sunburst, and other native Plotly chart types supported by
Analytics. Supported dashboard card sizing and placement are retained.
USA-state choropleth maps using built-in state boundaries are also supported without loading
boundary data from an external service.

Sharing supports a restricted set of in-memory operations, including text cleanup, date grouping,
category ordering, axis and index reshaping, set-based column checks, local collection iteration,
arithmetic, numeric summaries, and subplot composition. A chart can render privately but use an
operation sharing does not support; the sharing dialog identifies the operation when possible.
Chart code that reads additional files, makes network requests, or depends on custom workspace
modules is not currently supported.

Each link can contain up to 20 charts. Each chart's saved source and query must return a complete
result of at most 10,000 rows before the chart's Python code and any saved transform run. This limit
counts input rows, not plotted points. Narrow the saved filters, use supported query aggregation,
or prepare a smaller pipeline output to reduce those rows. The entire prepared shared view,
including all charts in a shared dashboard, must fit within 5 MiB of serialized JSON.

Charts backed by authorized pipeline Parquet or table-shaped JSON outputs, including
dynamic-block outputs, are supported. Parquet-backed charts also support saved grouping with
count, sum, average, minimum, and maximum summaries. Sharing preserves the chart's saved output
and run/partition selection and requires a complete result.

PostgreSQL and MySQL charts support both sharing modes. Snapshot uses an eligible saved chart
when available, preserving its displayed data without rerunning SQL. Mage must verify that the
saved chart matches its current source and complete saved result. Missing, redacted, or failing
SQL does not block this kind of Snapshot. If no eligible saved chart exists, Snapshot uses the
normal query path and can fail. Its data time comes from the original saved result; if that time
cannot be established, the chart labels its data time as unavailable.

Live reruns the saved, read-only query during scheduled refreshes. Configure read-only database
credentials in the workspace connection profile. Mage checks the creator's workspace permissions
when a recipient opens either type of link. Sharing a saved Snapshot does not recheck current
database grants; revoke its link to withdraw the prepared view.

If a fresh SQL query cannot complete, sharing can fail or use an eligible saved
result. Refresh the private chart, narrow or optimize its query, and retry. Live
sharing requires a saved, credential-free query.

Saved results can include rows visible at capture even if current row-level
policies exclude them. Refresh the private chart before sharing if those
policies have changed.

Charts that depend on external resources, unsupported data sources, or configurations that cannot be
safely prepared for public viewing remain unsupported. Examples include maps that require external
GeoJSON, tiles, or access tokens, external images, and custom buttons that replace chart data or layout. Recipients receive the prepared chart
data; their interactions cannot run chart code or request additional source data.

Dashboard sharing requires every included chart to be eligible. If preparation fails, no
usable link is created; share an eligible chart individually or create a separate dashboard.
If saved source outputs are missing or have expired, complete a new run of the source pipeline
and select its output before creating a link.

### Manage and revoke links

Open **Manage links** from either **Share** or **Share chart** to see the same active dashboard
and chart links for that dashboard. Editors see only links they created; Admins and Owners can
also see and manage other users' links.

- Select a link's row to copy or regenerate it. Regeneration invalidates
  the previous link and its access sessions.
- A lock icon means **Access code required**.
- Click the trash action and confirm to revoke a link. Admins and Owners can also use
  **Delete all shared links** from either sharing modal to revoke links for the dashboard and
  its charts.
- Expired, revoked, and invalidated links disappear from the table. Their audit history remains.

After a sharing security update, older links may become unavailable. Create new links for
recipients if this happens.

Dashboard renames and chart display-name changes preserve links. If renaming a chart also
changes its saved code, a Live link may require replacement when Mage cannot verify that only
the displayed title changed. Deleting a source dashboard or chart, removing a shared chart from
its dashboard, moving it outside its workspace, or losing required permissions makes the affected
link unavailable. Changes to a live link's source, fields, or query scope require a replacement
link with a new acknowledgment. If Mage temporarily cannot read workspace metadata to verify
access, the link can be retried after the metadata becomes available.

If a live refresh is delayed or the source is temporarily unavailable, recipients can see the
last successful data for up to 24 hours after that refresh, with a notice that the data may be
outdated. Authorization failures never permit stale data delivery. Invalid links show a safe
unavailable state without exposing internal resource details. Access sessions
expire after one hour; recipients can reopen the original link to establish a new session while
the link remains valid.

Creation, access, changes, regeneration, and revocation are recorded in the workspace audit
history. Anonymous access identifies a shared link, not a verified person. Revocation prevents
future access; it cannot retract information a recipient has already seen or copied.

## Recommended dashboard patterns

### Executive dashboard

Use this for a high-level business review. Start with scorecards and simple trends, then add a few
breakdowns that explain why the numbers changed.

Example charts:

1. Monthly recurring revenue.
1. New, expansion, contraction, and churned revenue.
1. Net revenue retention by segment.
1. Top growing accounts.
1. Accounts at risk.

### Product dashboard

Use this for adoption, activation, and engagement analysis.

Example charts:

1. Weekly active users by plan.
1. Activation funnel by signup cohort.
1. Feature adoption by account tier.
1. Retention by cohort.
1. Most common user paths or events.

### Data quality dashboard

Use this for operational trust in your pipelines and datasets.

Example charts:

1. Failed records by source.
1. Validation errors by type.
1. Freshness by table or pipeline.
1. Duplicate records over time.
1. Missing values by field.

### Model quality dashboard

Use this for ML and AI workflows where stakeholders need to see model behavior over time.

Example charts:

1. Accuracy, recall, and precision by evaluation date.
1. Prediction volume by class.
1. Drift by feature.
1. Confusion matrix summary.
1. Experiment comparison by metric.

## Best practices

1. Start with the decision the dashboard should support.
1. Use plain-language chart titles, such as `Revenue by plan` or `Failed records by source`.
1. Group charts by story: summary, drivers, segments, and diagnostics.
1. Keep raw-detail tables secondary unless the dashboard is for debugging or operations.
1. Use AI edits to iterate quickly, then keep the clearest version.
1. Create separate dashboards for separate audiences.
1. Refresh dashboards before recurring business reviews.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| The dashboard is empty | Create a dashboard, then add at least one chart from data available in Mage. |
| Sidekick cannot create a chart | Run the relevant pipeline or block so there is data to inspect, then try **Add chart** again. |
| A chart shows no data | Check whether the selected data is empty, filtered too narrowly, or missing the metric you asked for. |
| Refresh fails | Confirm the source data is still available and retry. The previous dashboard view remains available. |
| The dashboard feels too busy | Split it into separate dashboards by audience or decision, then keep only the most important charts on each one. |
| The layout feels crowded on a small screen | Charts stack on compact screens. Use a desktop browser for precise dashboard layout work. |
